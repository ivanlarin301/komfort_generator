# Проект карточек товаров Komfort

## Назначение

Этот каталог используется для подготовки коммерческих изображений товаров по Excel-каталогу и локальным исходным фотографиям.

## Постоянные правила

- Для запросов на анализ каталога, группировку вариантов, генерацию, проверку или продолжение генерации карточек обязательно используй навык `marketplace-product-cards` из `.agents/skills/marketplace-product-cards/SKILL.md`.
- Пользовательская задача определяет объём запуска: один товар, выбранные товары, одна папка или весь каталог. Не расширяй объём без явного указания.
- Исходные Excel-файлы и содержимое `images/` считаются неизменяемыми источниками. Не перезаписывай и не удаляй их.
- Для каждого входного Excel создавай отдельный запуск в `output/product-cards/<имя-Excel-без-расширения>/`. Внутри храни манифест, папки карточек и выходную копию Excel. Не смешивай результаты разных каталогов.
- Не публикуй и не загружай результаты во внешние сервисы без отдельной просьбы пользователя.
- Если часть товаров не готова из-за отсутствующих или сомнительных фотографий, обработай остальные и явно пометь проблемные позиции. Не подменяй отсутствующий товар похожим.
- Запрос только на анализ, план или аудит не разрешает генерацию изображений.

## Источники проекта

- Excel-каталог: указанный пользователем `.xlsx`; если он не указан, выбери наиболее подходящий непустой файл, игнорируя временные файлы `~$*.xlsx`, и сообщи, какой файл выбран.
- Исходные изображения: `images/<наименование товара>/`. В выходном Excel указывай относительные пути и кликабельные ссылки на эти локальные файлы, а также на готовые карточки.
- Существующие скрипты загрузки и разбора можно запускать только когда это входит в задачу. Перед запуском проверь их входные файлы и ожидаемые выходы.

## Приоритет инструкций

Явные требования пользователя имеют приоритет над этим файлом и правилами навыка. При конфликте сохрани исходные данные и останови только ту часть работы, для которой действительно нужен выбор пользователя.

## Git и резервная копия

- После каждого изменения проекта проверь `git status`, добавь только относящиеся к задаче файлы, создай содержательный коммит и выполни `git push` в `origin`.
- Не включай в коммиты временные файлы, кэш, Excel lock-файлы и секреты. Если push не удался, сообщи причину пользователю и не заявляй, что резервная копия создана.
