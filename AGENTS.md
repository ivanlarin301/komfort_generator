# Проект карточек товаров «Комфорт»

## Назначение

Система собирает карточки товаров для Instagram (4:5, 1080×1350) в фирменном дизайне из Canva владельца.
- **Вход:** фото товаров и таблица (код, название, цена, данные), строка N = фото N.
- **Выход:** готовые PNG.

Карточка состоит из двух слоёв:
1. **Фотография товара в сцене.** Генерация рисует её по фото оператора как референсу: товар объёмный, на поверхности, со студийным светом, тенью и отражениями, как с профессиональной фотосессии. Сцены разные внутри партии.
2. **Фирменный текстовый слой**: заголовок, плашки, код, цена, логотип. Его всегда одинаково рисует шаблон кодом, генерация текст не рисует.

## Постоянные правила

- Для любых запросов про карточки используй навык `komfort-cards` из `.agents/skills/komfort-cards/SKILL.md`: сделать, переделать, проверить, продолжить партию.
- **Товар генерируется в сцене (режим `scene`) — всегда.** Вклейка вырезки (режим `composite`) разрешена только если оператор в этом чате прямо попросил вклеить конкретный товар. Его слова записываются в `layout.composite_reason`. Сам вклейку не выбирай, даже ради точности этикетки: владелец решил, что упрощение мелкого текста допустимо.
- Не придумывай обходы: никаких своих масок, SVG, ручного монтажа и правок файлов в `_work/` вручную. Только команды `.\cards.cmd` и поля `batch.json`, описанные в навыке.
- Объём работы определяет оператор: одна позиция, несколько или вся партия. Не расширяй его без явной просьбы.
- Исходные фото, таблицы и содержимое `images/` не изменяй и не удаляй. Каждая партия живёт в своей папке `output/<партия>/`, файлы карточек не перезаписываются.
- Не публикуй и не загружай результаты во внешние сервисы без отдельной просьбы.
- Если часть позиций не готова (нет фото, данных, брак генерации), сделай остальные и явно перечисли проблемные с причинами. Не подменяй товар похожим.
- Запрос только на анализ, план или проверку не разрешает генерацию изображений.
- Python и скрипты запускай только через `.\cards.cmd`. Если окружения нет, попроси оператора запустить `УСТАНОВКА.bat`.

## Приоритет инструкций

Явные требования владельца и оператора выше этого файла и правил навыка. При конфликте сохрани исходные данные и останови только ту часть работы, для которой нужен выбор человека.

## Git

- Коммиты нужны только при изменениях самой системы: код, шаблоны, навык, `config/`. Партии карточек (`output/`, `input/`) в git не попадают.
- После изменения системы проверь `git status`, добавь только относящиеся к задаче файлы, создай содержательный коммит и выполни `git push` в `origin`.
- Не включай в коммиты временные файлы, кэш, `.venv/`, `.models/`, Excel и секреты. Если push не удался, сообщи причину и не заявляй, что резервная копия создана.
- На рабочем компьютере оператора систему не меняй — только делай карточки.

## Где что лежит

- `.kiro/specs/canva-style-cards/` — спецификация: требования, дизайн, задачи.
- `templates/stroyka/` — шаблон текстового слоя (главный шаблон, одобрен владельцем).
- `config/scenes.yaml` — промпты сцен по категориям; `config/icons.yaml` — иконки-свойства.
- `komfort_cards/` — команды `cards.cmd`.
- `legacy/` — старая система, не используется.
